# Contributing

1. Create a focused branch from `main`.
2. Keep secrets and customer data out of commits and logs.
3. Add or update tests for behavior changes.
4. Run `npm run validate` before opening a pull request.
5. Use a pull request with a clear risk description and rollback plan.

Changes require passing CI and review. Production releases use semantic version tags. Breaking API changes require migration notes and a versioned endpoint strategy.
